# 기술 문서

Warriors: Legends of Troy (PS3, BLES01183)의 데이터 형식과 한글패치 적용 방식을 정리한 문서입니다.
모든 값은 따로 적지 않은 한 빅엔디언(BE)입니다.

## 1. 디렉터리 구성

```
PS3_GAME/USRDIR/PS3/
├─ Localization/<DEU|ENG|FRA|ITA|SPA>/   언어별 텍스트 (INI)
├─ TrojanMusou/Fonts/fonts.g1n            게임 비트맵 글꼴
├─ TrojanMusou/Fonts/fonts_JP.g1n         일본어 글꼴 (유럽판에서는 쓰이지 않음)
├─ StartupCommonPackage_<LANG>.cpkg       부팅 시 읽는 묶음 (버튼 기호 정의 등)
├─ LocalizedCommonPackage_<LANG>.cpkg     언어별 공통 UI 텍스처
├─ LocalizedUIGameModePackage_<LANG>.mpkg 메인 메뉴·장 선택·부록 화면 텍스처
├─ CommonMasterPackage.cpkg               HUD 등 공통 데이터
└─ Campaign*.mpkg, C0*.mpkg, *.pam       장별·캐릭터별 데이터
```

한글패치는 영어(`ENG`) 데이터를 교체합니다. 시스템 언어를 영어로 두어야 하는 이유입니다.

## 2. 텍스트 (INI)

- 인코딩: UTF-16BE, BOM 있음, 줄바꿈 CRLF
- 구조: `[섹션]`과 `키=값`. 값 안의 `\n`은 실제 줄바꿈이 아니라 화면 줄바꿈 표시입니다.
- 파일 99개
  - `UIStringsENG.ini`: 메뉴, 도움말, 아이템, 로딩 팁
  - `Scenario###ENG.ini`: 장별 목표, 튜토리얼
  - `SubTitle###ENG.ini`: 인게임 대사. 키에 화자 이름이 들어 있습니다(예: `00030X_G01_Patroklos[0]`).
  - `SubTitleFMV###ENG.ini`: 컷신 자막

### 태그

| 형식 | 예 | 의미 |
|---|---|---|
| `<...>` | `<Settings.ControlSet.QuickAttack>`, `<Console:A>` | 버튼 아이콘, 변수 |
| `{...}` | `{l1}{r1}`, `{start}`, `{rarrow}` | 버튼 기호 (StartupCommonPackage의 `ButtonCodeStrings`에 정의) |
| 문장부호 태그 | `{’}` `{‘}` `{—}` `{…}` `{™}` | 원본 글꼴이 Latin-1 범위만 가지고 있어서 태그로 출력하는 문장부호 |
| `%d`, `%02d` | | 숫자 서식 |

## 3. 글꼴 (G1N)

### 헤더

| 오프셋 | 크기 | 내용 |
|---|---|---|
| 0x00 | 8 | `G1N_0000` |
| 0x08 | 4 | 파일 크기 |
| 0x0C | 4 | 첫 글꼴 표 오프셋 |
| 0x10 | 4 | 1 |
| 0x14 | 4 | 글리프 데이터 시작 오프셋 |
| 0x18 | 4 | 팔레트 수 (40) |
| 0x1C | 4 | 글꼴 수 (7) |
| 0x20 | 4×글꼴 수 | 글꼴 표 오프셋 |
| 0x3C | 64×팔레트 수 | 팔레트. 16색 × ARGB 4바이트 |

### 글꼴 표

글꼴마다 다음 순서로 이어집니다.

1. `u16[65536]`: UCS-2 코드 포인트를 글리프 번호로 바꾸는 표. 0이면 글리프가 없다는 뜻입니다.
   유니코드 BMP 전체를 가리킬 수 있어서, 한글은 코드 포인트(U+AC00~)에 바로 등록하면 됩니다.
2. 글리프 항목 12바이트 × 글리프 수

| 바이트 | 내용 |
|---|---|
| 0 | 폭 |
| 1 | 높이 |
| 2 | x 오프셋 (0) |
| 3 | 높이 계열 값 (대문자는 높이와 같음) |
| 4 | **진행 폭**. 엔진이 다음 글자까지의 간격으로 사용 (실측으로 확인) |
| 5 | y 오프셋 (부호 있음, 약 -높이/2) |
| 6 | 0 |
| 7 | 줄 높이 |
| 8–11 | 글리프 데이터 시작부터의 오프셋 |

### 글리프 비트맵

- 4bpp 인덱스, 상위 니블이 먼저, 한 줄 = `ceil(폭/2)` 바이트
- 인덱스 의미 (일반 팔레트 기준)
  - 0: 투명
  - 1–7: 검정 알파 단계 (외곽선, 그림자)
  - 8–14: 불투명 밝기 단계 (글자 면)
- 3번 글꼴은 금빛·은빛 입체 팔레트를 쓰며, 같은 인덱스 체계로 음영을 표현합니다.

### 글꼴 구성

| 번호 | 크기 | 용도 | 한글 |
|---|---|---|---|
| 0 | 22px | 굵은 본문 (자막, 안내문) | IBM Plex Sans KR SemiBold |
| 1 | 30px | 큰 본문 | 고운돋움 (약간 굵게) |
| 2 | 22px | 가는 본문 | 고운돋움 |
| 3 | 30px | 장식 대문자 (화자 이름, HUD, 「보조 목표」) | 본명조 Black + 입체 음영 |
| 4 | 24×25 | 숫자 1–9 | 변경 없음 |
| 5 | 24px | 버튼 아이콘 (U+0808–0814) | 변경 없음 |
| 6 | 48×24 | U+0806 | 변경 없음 |

### 한글 추가 방법

1. 번역문에 쓰인 글자(한글 825자, 「」)만 뽑습니다.
2. 글꼴별로 4배 해상도로 그린 뒤 줄여서 안티앨리어싱합니다. 원본처럼 외곽선(팽창), 그림자(이동+흐림), 입체 음영(기울기 기반 조명)을 입혀 4bpp 인덱스로 바꿉니다.
3. 기존 글리프는 그대로 두고, 항목과 비트맵을 뒤에 덧붙입니다. 코드표를 갱신하고 오프셋을 다시 계산합니다.
4. 진행 폭을 그림 폭보다 2px(3번 글꼴은 4px) 작게 잡아 외곽선 여백만큼 글자 사이를 좁혔습니다.

## 4. 묶음 파일 (cpkg / mpkg)

### 압축 컨테이너

```
u32 N                         청크 수
u32 offsets[N-1]              2번째 청크부터의 위치 (4×N 지점 기준)
반복 N회:
  u32 compressedSize
  zlib 스트림                  풀면 65,536바이트 (마지막 청크는 더 작을 수 있음)
u32 0                         끝 표시
```

다시 묶을 때는 내용이 바뀐 청크만 새로 압축하고, 나머지는 원본 압축 바이트를 그대로 씁니다.
예를 들어 `CommonMasterPackage.cpkg`는 725개 중 2개만 새로 압축했습니다. 이렇게 하면 차분 패치가 작아집니다.

### 풀린 데이터

- 시작: `7C F9 EB F1 'PS3\0'`, UTF-16 묶음 이름, `ROOT`
- ASCII 섹션 이름(예: `UITextures04Scenario`)과 `Texture` 유형 항목, UTF-16 애셋 이름 뒤에 G1T 텍스처가 이어집니다.
- 텍스처는 섹션 안에서 이름으로 참조됩니다(예: `UITextures04Scenario.Texture.STitle_G001`).

## 5. 텍스처 (G1T)

| 오프셋 | 내용 |
|---|---|
| 0x00 | `G1TG0060` |
| 0x08 | 크기 |
| 0x0C | 오프셋 표 위치 |
| 0x10 | 텍스처 수 |

텍스처 헤더:

| 바이트 | 내용 |
|---|---|
| 0 | 0x01 |
| 1 | 형식: 0x06 = DXT1, 0x08 = DXT5 |
| 2 | 크기: 상위 니블 = log2(폭), 하위 니블 = log2(높이) |
| 3–7 | 플래그 |
| 8–11 | 확장 헤더 길이 (0x0C) |

그 뒤에 DXT 데이터가 스위즐 없이 이어집니다. 같은 형식·크기로 다시 인코딩해 그 자리에 덮어쓰므로 묶음 구조는 바뀌지 않습니다.

### 교체한 텍스처

| 묶음 | 텍스처 | 내용 |
|---|---|---|
| LocalizedCommonPackage_ENG | `STitle_G*`, `STitle_T*`, `STitle_C*` (27) | 장·도전 제목 |
| 〃 | `Pause_Title`, `Result_Text`, `Game_Over_Text`, `ChallengeResult_Text`, `Options_Title` | 화면 제목 |
| LocalizedUIGameModePackage_ENG | `Main_BG2` | 메인 메뉴(선택/기본), 인물 이름표 8명 |
| 〃 | `Main_BG` | 도전, 장 선택(비활성), 아이템, 기술 |
| 〃 | `Chap_Title`, `Extras_Title`, `Title_Parts`, `Chap_Difficulty` | 장 선택·부록 제목, 시작 안내, 난이도 |
| CommonMasterPackage | `Fury_Parts` | HUD 「KLEOS」(세로로 회전된 상태) |

### 다시 그리는 방법

1. 아틀라스 안의 글자 조각은 알파 채널 연결 요소로 자동 검출합니다. 게임이 쓰는 UV 영역을 넘지 않도록 원래 상자 안에 그립니다.
2. 원본 글자에서 줄별 면 색(그라데이션), 외곽선 색, 테두리 색을 뽑아 한글에 그대로 입힙니다.
3. 비활성(검정·반투명) 변형은 원본의 최대 알파를 유지합니다.
4. 난이도 표시는 고리의 원을 맞춘 뒤, 원래 글자가 차지하던 각도 범위에 글자를 하나씩 기울여 배치합니다.

## 6. 패치 형식과 ISO 적용

### 차분 데이터 (`TROYKO01`, zlib 압축, 리틀엔디언)

```
"TROYKO01"  u32 파일수
파일마다:
  u16 경로길이, 경로(UTF-8, ISO 루트 기준)
  u64 원본크기, [20] 원본 SHA-1, u64 결과크기, [20] 결과 SHA-1
  u32 연산수, 연산마다:
    u8 0 = COPY: u64 원본오프셋, u64 길이
    u8 1 = ADD : u64 길이, 바이트
```

차분은 64바이트 블록 기준 롤링 해시로 만듭니다. 103개 파일, 결과 37.8MB 가운데 새로 담기는 바이트는 약 2.2MB입니다.

### ISO 적용 과정

1. ISO9660 기본 볼륨 기술자와 Joliet 보조 기술자의 디렉터리 트리를 모두 읽습니다.
2. `PS3_GAME/PARAM.SFO`의 `TITLE_ID`, 원본 파일의 SHA-1을 확인합니다.
3. 결과 파일이 원래 차지하던 섹터 안에 들어가면 그 자리에, 아니면 ISO 끝에 2048바이트 단위로 덧붙입니다.
4. 두 트리의 디렉터리 레코드에서 위치(LBA)와 크기(양쪽 엔디언)를 고칩니다.
5. 크기가 늘었으면 볼륨 기술자의 볼륨 크기와 PS3 섹터 0의 영역 표 마지막 끝 섹터를 갱신합니다.
6. 디렉터리를 다시 읽어 모든 결과 파일의 SHA-1을 검증합니다.
